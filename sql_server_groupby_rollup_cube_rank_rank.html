1. One small dataset we will use throughout

Imagine a company has sales in several regions. Each sale has:

  • Region — where the sale happened
  • Salesperson — who made the sale

For the examples below, we can create a temporary SQL Server table:

2. GROUP BY — make groups and calculate summaries

2.1 Why do we need GROUP BY?

Suppose we ask: How much did each region sell? There are many rows in the table, but we want one result row per region. That is exactly the kind of problem GROUP BY solves. 

SELECT
    Region,
    SUM(SalesAmount) AS TotalSales
FROM #Sales
GROUP BY Region;
RegionTotalSales
East2505
West2290

The database conceptually does this:

Original rows | v +----------------+ | Group by Region| +----------------+ | +---- East ----> 2505 | +---- West ----> 2290

2.2 What is an aggregate function?

An aggregate function takes multiple rows and produces a summary value. Common examples are:

FunctionMeaningExample
SUM()Add valuesSUM(SalesAmount)
AVG()Calculate averageAVG(SalesAmount)
COUNT()Count rows/valuesCOUNT(*)
MIN()Smallest valueMIN(SalesAmount)
MAX()Largest valueMAX(SalesAmount)

2.3 GROUP BY can use more than one column

Now ask a more detailed question:

How much did each salesperson sell for each product?

SELECT
    Salesperson,
    Product,
    SUM(SalesAmount) AS TotalSales
FROM #Sales
GROUP BY
    Salesperson,
    Product;

Now the group is not just a salesperson. It is the combination (Salesperson, Product).

Salesperson + Product | +--> Alice + Laptop +--> Alice + Mouse +--> Bob + Laptop +--> Bob + Mouse +--> Carol + Laptop +--> Carol + Mouse +--> David + Laptop +--> David + Mouse
Key mental model: GROUP BY controls the level of detail of the result. If you group by Region, you get one row per region. If you group by Region and Product, you get one row per region/product combination.

2.4 A common mistake

If a column appears in SELECT and is not inside an aggregate function, it generally needs to be included in GROUP BY. 

-- Correct
SELECT Region, SUM(SalesAmount)
FROM #Sales
GROUP BY Region;

This is not valid:

-- Invalid in SQL Server
SELECT Region, Salesperson, SUM(SalesAmount)
FROM #Sales
GROUP BY Region;

Why? SQL Server would not know which single salesperson should be displayed for a region that contains several salespeople.

3. COALESCE — replace NULL with a value

3.1 First understand NULL

NULL means the value is missing or unknown. It is not the same thing as zero, an empty string, or the word "NULL". 

SELECT
    COALESCE(NULL, 'Unknown') AS Result;

Result:

Result
Unknown

3.2 What does COALESCE do?

COALESCE checks its arguments from left to right and returns the first non-NULL value. 

SELECT
    COALESCE(NULL, NULL, 'Hello', 'World') AS Result;

Result: Hello.

Another example:

SELECT
    COALESCE(PhoneNumber, 'No phone number')
FROM Students;

If PhoneNumber is NULL, SQL Server displays No phone number instead.

3.3 COALESCE with GROUP BY results

This becomes especially important when we later use ROLLUP and CUBE, because those operations intentionally create NULLs to represent higher-level summary rows.

For example, a ROLLUP result might contain:

RegionProductTotalSales
EastLaptop2400
EastMouse105
EastNULL2505

The NULL in Product does not necessarily mean that the product is unknown. Here it means: this row is the total for all products in East.

You can make the output easier to read:

SELECT
    Region,
    COALESCE(Product, 'All Products') AS Product,
    SUM(SalesAmount) AS TotalSales
FROM #Sales
GROUP BY ROLLUP (Region, Product);
Important: COALESCE changes how NULL is displayed; it does not tell you whether a NULL came from missing source data or from a subtotal generated by ROLLUP/CUBE. For that distinction, SQL Server provides GROUPING() and GROUPING_ID(), explained later.

4. ROLLUP — add subtotals and a grand total

4.1 Why do we need ROLLUP?

Ordinary GROUP BY gives us detailed groups. But reports often need several levels:

Region + Product totals | v East / Laptop East / Mouse West / Laptop West / Mouse Then subtotals: East / ALL PRODUCTS West / ALL PRODUCTS Then grand total: ALL REGIONS / ALL PRODUCTS

ROLLUP is designed for this hierarchical type of report.

4.2 Basic ROLLUP syntax

SELECT
    Region,
    Product,
    SUM(SalesAmount) AS TotalSales
FROM #Sales
GROUP BY ROLLUP (Region, Product);

With ROLLUP(Region, Product), SQL Server produces these levels:

  1. Region + Product
  2. Region subtotal
  3. Grand total
RegionProductTotalSalesMeaning
EastLaptop2400East + Laptop
EastMouse105East + Mouse
EastNULL2505East subtotal
WestLaptop2200West + Laptop
WestMouse90West + Mouse
WestNULL2290West subtotal
NULLNULL4795Grand total

4.3 Why is it called ROLLUP?

Think of the report as moving upward through a hierarchy:

Detailed: Region + Product | v Roll up Product: Region | v Roll up Region: Grand Total

The order matters. With ROLLUP(Region, Product), Product is rolled up first, then Region.

4.4 ROLLUP with three columns

GROUP BY ROLLUP (Region, Salesperson, Product)

Conceptually, the grouping levels are:

LevelGrouping
1Region + Salesperson + Product
2Region + Salesperson
3Region
4Grand total
Remember: ROLLUP is especially useful when your columns form a natural hierarchy, such as Year → Quarter → Month or Country → State → City.

5. CUBE — calculate every combination of dimensions

5.1 Why do we need CUBE?

Now suppose management wants to analyze sales from every possible angle:

  • Region and Product
  • Region only
  • Product only
  • Everything combined

This is where CUBE is useful.

5.2 Basic CUBE syntax

SELECT
    Region,
    Product,
    SUM(SalesAmount) AS TotalSales
FROM #Sales
GROUP BY CUBE (Region, Product);

For two grouping columns, CUBE produces every combination:

RegionProductMeaning
EastLaptopEast + Laptop
EastMouseEast + Mouse
WestLaptopWest + Laptop
WestMouseWest + Mouse
EastNULLEast subtotal
WestNULLWest subtotal
NULLLaptopLaptop subtotal across all regions
NULLMouseMouse subtotal across all regions
NULLNULLGrand total

5.3 Think of CUBE as a set of questions

CUBE(Region, Product) Question 1: What is East + Laptop? Question 2: What is East + Mouse? Question 3: What is West + Laptop? Question 4: What is West + Mouse? Question 5: What is East, regardless of Product? Question 6: What is West, regardless of Product? Question 7: What is Laptop, regardless of Region? Question 8: What is Mouse, regardless of Region? Question 9: What is the grand total?

5.4 CUBE with three columns

With three dimensions, CUBE produces 2³ = 8 grouping combinations before considering the individual values within those combinations. 

GROUP BY CUBE (Region, Salesperson, Product)

The grouping combinations are:

Combination
Region + Salesperson + Product
Region + Salesperson
Region + Product
Salesperson + Product
Region
Salesperson
Product
Grand total
Performance note: CUBE can produce many grouping combinations. As the number of dimensions increases, the number of combinations grows rapidly. Use it deliberately, especially on large datasets.

6. ROLLUP vs CUBE — compare them now

At this point we have learned both operations independently. Now the difference is much easier to understand.

6.1 The central difference

ROLLUPCUBE
Creates hierarchical levels of aggregation. Creates every combination of the specified grouping columns.
Useful when the dimensions have an order or hierarchy. Useful when you want analysis from multiple independent dimensions.
ROLLUP(Region, Product) gives Region+Product, Region, Total. CUBE(Region, Product) gives Region+Product, Region, Product, Total.
Fewer grouping combinations in many cases. More combinations; can create substantially more rows.

6.2 Visual comparison

ROLLUP(Region, Product) Region + Product | v Region | v Grand Total CUBE(Region, Product) Region + Product Region Product Grand Total All possible combinations are included.

6.3 The most important example

ROLLUP:

GROUP BY ROLLUP (Region, Product)

includes a Region subtotal, but does not independently produce a Product subtotal.

CUBE:

GROUP BY CUBE (Region, Product)

includes both:

  • Region subtotals
  • Product subtotals
  • Region + Product detail
  • Grand total
Simple memory trick: ROLLUP = move upward through a hierarchy. CUBE = look at the data from every combination of dimensions.

7. GROUPING and GROUPING_ID — identify subtotal rows

Once you use ROLLUP or CUBE, you will see NULLs. But a NULL may have two very different meanings:

  1. The original data really contains NULL.
  2. ROLLUP/CUBE generated NULL to represent an aggregate level.

SQL Server provides GROUPING() to help distinguish these situations.

7.1 GROUPING()

SELECT
    Region,
    Product,
    GROUPING(Region) AS IsRegionSubtotal,
    GROUPING(Product) AS IsProductSubtotal,
    SUM(SalesAmount) AS TotalSales
FROM #Sales
GROUP BY ROLLUP (Region, Product);

For a normal detail row, the grouping flag is 0. For a column that has been rolled up in that row, the grouping flag is 1.

RegionProductGROUPING(Region)GROUPING(Product)Meaning
EastLaptop00Detail row
EastNULL01East subtotal
NULLNULL11Grand total

7.2 GROUPING_ID()

GROUPING_ID() combines multiple grouping flags into one integer. It is useful when a report needs to identify aggregation levels programmatically. 

SELECT
    Region,
    Product,
    GROUPING_ID(Region, Product) AS GroupingLevel,
    SUM(SalesAmount) AS TotalSales
FROM #Sales
GROUP BY ROLLUP (Region, Product);

GROUPING tells you whether NULL represents a grouping-generated subtotal.

8. RANK — assign positions while preserving ties

GROUP BY, ROLLUP and CUBE are about aggregation. Ranking is different: ranking compares rows and assigns a position.

8.1 Start with a simple question

Suppose we want to rank salespeople by total sales. First, calculate the total for each salesperson: 

SELECT
    Salesperson,
    SUM(SalesAmount) AS TotalSales
FROM #Sales
GROUP BY Salesperson;

Now we have one row per salesperson. We can rank those rows. 

SELECT
    Salesperson,
    TotalSales,
    RANK() OVER (ORDER BY TotalSales DESC) AS SalesRank
FROM
(
    SELECT
        Salesperson,
        SUM(SalesAmount) AS TotalSales
    FROM #Sales
    GROUP BY Salesperson
) AS SalesTotals;

8.2 What does RANK() do?

Suppose the values are:

PersonScoreRANK()
A1001
B902
C902
D804

B and C are tied for second. Therefore the next rank is 4, not 3. This is called a ranking gap.

100 --> Rank 1 90 --> Rank 2 90 --> Rank 2 80 --> Rank 4 ^ | Rank 3 is skipped

8.3 PARTITION BY: rank separately inside groups

Suppose we want to rank salespeople within each region, rather than across the entire company. 

SELECT
    Region,
    Salesperson,
    TotalSales,
    RANK() OVER
    (
        PARTITION BY Region
        ORDER BY TotalSales DESC
    ) AS RegionalRank
FROM
(
    SELECT
        Region,
        Salesperson,
        SUM(SalesAmount) AS TotalSales
    FROM #Sales
    GROUP BY Region, Salesperson
) AS RegionalTotals;

PARTITION BY Region means: start a separate ranking competition for each region.

West Alice -> Rank 1 Bob -> Rank 2 East Carol -> Rank 1 David -> Rank 2
Window function idea: RANK() does not collapse rows into one row per group. It calculates a value for each row while keeping the rows available in the result.

9. DENSE_RANK — ranking without gaps

DENSE_RANK() is similar to RANK(), but it does not skip a number after a tie. 

SELECT
    Person,
    Score,
    DENSE_RANK() OVER (ORDER BY Score DESC) AS DenseRank
FROM Scores;

Using the same scores:

PersonScoreDENSE_RANK()
A1001
B902
C902
D803

There is no skipped rank. The next distinct score gets rank 3.

100 --> Dense Rank 1 90 --> Dense Rank 2 90 --> Dense Rank 2 80 --> Dense Rank 3 ^ | No rank is skipped

9.1 Why might this be useful?

Imagine exam scores:

StudentScore
Anna95
Ben90
Chris90
David85

If you want the positions in a traditional competition ranking, use RANK(). If you want each distinct score to represent the next rank number without gaps, use DENSE_RANK().

10. RANK vs DENSE_RANK — compare after learning both

FeatureRANK()DENSE_RANK()
Handles ties Yes Yes
Same tied values get the same rank Yes Yes
Skips a rank after a tie Yes No
Example for 100, 90, 90, 80 1, 2, 2, 4 1, 2, 2, 3

10.1 One more ranking function: ROW_NUMBER()

SQL Server also has ROW_NUMBER(). It is useful to understand because it shows what makes RANK and DENSE_RANK different. 

ROW_NUMBER() OVER (ORDER BY Score DESC)

For 100, 90, 90, 80, the row numbers are:

ScoreROW_NUMBER()RANK()DENSE_RANK()
100111
90222
90322
80443
Three-way memory trick:
ROW_NUMBER = every row gets a unique number.
RANK = ties share a rank, and gaps are created.
DENSE_RANK = ties share a rank, but no gaps are created.

11. Practice questions

Question 1
Write a query that calculates total sales for each Region. 
SELECT
    Region,
    SUM(SalesAmount) AS TotalSales
FROM #Sales
GROUP BY Region;
Question 2
Write a query that calculates total sales for each Region and Product. 
SELECT
    Region,
    Product,
    SUM(SalesAmount) AS TotalSales
FROM #Sales
GROUP BY Region, Product;
Question 3
What does this do? COALESCE(PhoneNumber, 'No Phone')
It returns PhoneNumber when it is not NULL. If PhoneNumber is NULL, it returns 'No Phone'.
Question 4
What levels does ROLLUP(Region, Product) create?
Region + Product, then Region subtotal, then the grand total.
Question 5
What extra subtotal can CUBE(Region, Product) produce that ROLLUP(Region, Product) does not independently produce?
A Product subtotal across all regions.
Question 6
For scores 100, 90, 90, 80, what are the RANK and DENSE_RANK values?
RANK = 1, 2, 2, 4
DENSE_RANK = 1, 2, 2, 3
Question 7
What does PARTITION BY do in a ranking window function?
It divides the rows into separate groups for the calculation. For example, PARTITION BY Region makes the ranking restart separately for each Region.

12. Quick reference

ConceptMain purposeBasic syntax
GROUP BY Group rows so aggregate functions can summarize each group. GROUP BY Region
COALESCE Return the first non-NULL value. COALESCE(column, 'Default')
ROLLUP Create hierarchical subtotals and a grand total. GROUP BY ROLLUP(Region, Product)
CUBE Create all grouping combinations of the specified dimensions. GROUP BY CUBE(Region, Product)
GROUPING Identify whether a NULL was generated by a grouping operation. GROUPING(Product)
RANK Rank rows; ties share a rank and gaps can occur. RANK() OVER (ORDER BY Score DESC)

The whole lesson in one picture

SQL REPORTING | +----------------+----------------+ | | AGGREGATION RANKING | | GROUP BY +--------+--------+ | | | | +----+----+ ROW_NUMBER RANK DENSE_RANK | | COALESCE Subtotals | +----+----+ | | ROLLUP CUBE | | hierarchy all combinations
Recommended learning order: First become comfortable with GROUP BY and aggregate functions. Then learn how COALESCE handles NULL. Then learn ROLLUP and CUBE. After you understand both, compare them. Finally learn window functions such as RANK and DENSE_RANK, because ranking is a different problem from aggregation.
