1. Setup: Create a safe practice database

Step 1. Open SSMS, connect to a SQL Server instance, and select New Query. Run the following batch. This tutorial uses its own database, StoredProcLab.

IF DB_ID('StoredProcLab') IS NULL
    CREATE DATABASE StoredProcLab;
GO
USE StoredProcLab;
GO

IF OBJECT_ID('dbo.Students', 'U') IS NULL
BEGIN
    CREATE TABLE dbo.Students (
        StudentID INT PRIMARY KEY,
        StudentName VARCHAR(60) NOT NULL,
        Age INT NOT NULL CHECK (Age BETWEEN 1 AND 120),
        Major VARCHAR(60) NOT NULL,
        GPA DECIMAL(3,2) NOT NULL CHECK (GPA BETWEEN 0 AND 4)
    );
END;
GO

IF NOT EXISTS (SELECT 1 FROM dbo.Students)
BEGIN
    INSERT INTO dbo.Students
        (StudentID, StudentName, Age, Major, GPA)
    VALUES
        (101, 'Ana', 20, 'Computer Science', 3.80),
        (102, 'Ben', 21, 'Mathematics', 3.40),
        (103, 'Cara', 22, 'Computer Science', 3.95),
        (104, 'David', 19, 'Business', 3.10),
        (105, 'Eva', 23, 'Mathematics', 3.70),
        (106, 'Frank', 21, 'Physics', 3.20);
END;
GO
SELECT * FROM dbo.Students ORDER BY StudentID;

Expected: Six student rows. StudentID is unique; GPA stores values from 0.00 through 4.00.

About GO: GO is a batch separator understood by SSMS and other SQL tools, not a SQL Server statement. A CREATE OR ALTER PROCEDURE statement must begin its own batch, so the examples use GO between procedure definitions.

2. What is a stored procedure?

A stored procedure is a named, saved collection of T-SQL statements in a database. You can execute it repeatedly without rewriting its statements. Procedures can return result sets, modify rows, call other procedures, and accept parameters.

Regular queryStored procedure
Write SELECT * FROM dbo.Students; each time.Create dbo.GetAllStudents once; run EXEC dbo.GetAllStudents; later.
SQL is submitted directly.SQL is saved in the database under a procedure name.

Basic syntax

CREATE OR ALTER PROCEDURE dbo.ProcedureName
AS
BEGIN
    SET NOCOUNT ON;
    -- SQL statements go here
END;
GO

EXEC dbo.ProcedureName;

CREATE OR ALTER creates a missing procedure or updates an existing one. SET NOCOUNT ON suppresses extra “N rows affected” messages; it does not suppress actual SELECT results. dbo is the schema name.

3. Non-parameterized procedures (no input needed)

A non-parameterized procedure has no parameters. Each execution performs the same defined task, although results can change as table data changes.

Example 1: Return all students

CREATE OR ALTER PROCEDURE dbo.GetAllStudents
AS
BEGIN
    SET NOCOUNT ON;
    SELECT StudentID, StudentName, Age, Major, GPA
    FROM dbo.Students
    ORDER BY StudentID;
END;
GO
EXEC dbo.GetAllStudents;

Expected: Six students, ordered by ID.

Example 2: Count students

CREATE OR ALTER PROCEDURE dbo.CountStudents
AS
BEGIN
    SET NOCOUNT ON;
    SELECT COUNT(*) AS TotalStudents FROM dbo.Students;
END;
GO
EXEC dbo.CountStudents;

Expected: TotalStudents = 6 before any data-changing examples.

Example 3: Show honor-roll students

CREATE OR ALTER PROCEDURE dbo.GetHonorRoll
AS
BEGIN
    SET NOCOUNT ON;
    SELECT StudentName, GPA
    FROM dbo.Students
    WHERE GPA >= 3.70
    ORDER BY GPA DESC;
END;
GO
EXEC dbo.GetHonorRoll;

Expected: Cara (3.95), Ana (3.80), Eva (3.70).

Example 4: Group by major

CREATE OR ALTER PROCEDURE dbo.CountByMajor
AS
BEGIN
    SET NOCOUNT ON;
    SELECT Major, COUNT(*) AS StudentCount
    FROM dbo.Students
    GROUP BY Major
    ORDER BY Major;
END;
GO
EXEC dbo.CountByMajor;

Expected: Business 1, Computer Science 2, Mathematics 2, Physics 1.

Example 5: Return two result sets

CREATE OR ALTER PROCEDURE dbo.StudentDashboard
AS
BEGIN
    SET NOCOUNT ON;
    SELECT COUNT(*) AS TotalStudents FROM dbo.Students;
    SELECT Major, AVG(GPA) AS AverageGPA
    FROM dbo.Students GROUP BY Major;
END;
GO
EXEC dbo.StudentDashboard;

Observe: SSMS displays two separate results grids: one overall count and one GPA summary.

4. Parameterized procedures

A parameterized procedure accepts values from the caller. Parameters begin with @ and have declared SQL data types.

Example 6: Search by student ID (INT parameter)

CREATE OR ALTER PROCEDURE dbo.GetStudentByID
    @StudentID INT
AS
BEGIN
    SET NOCOUNT ON;
    SELECT * FROM dbo.Students
    WHERE StudentID = @StudentID;
END;
GO
EXEC dbo.GetStudentByID @StudentID = 103;
EXEC dbo.GetStudentByID @StudentID = 101;

Expected: The first call returns Cara; the second returns Ana. @StudentID is an input parameter, not a table column.

Example 7: Search by major (text parameter)

CREATE OR ALTER PROCEDURE dbo.GetStudentsByMajor
    @MajorName VARCHAR(60)
AS
BEGIN
    SET NOCOUNT ON;
    SELECT StudentName, Major, GPA
    FROM dbo.Students
    WHERE Major = @MajorName;
END;
GO
EXEC dbo.GetStudentsByMajor @MajorName = 'Mathematics';

Expected: Ben and Eva.

Example 8: Two input parameters

CREATE OR ALTER PROCEDURE dbo.FindStudents
    @MajorName VARCHAR(60),
    @MinimumAge INT
AS
BEGIN
    SET NOCOUNT ON;
    SELECT StudentName, Age, Major
    FROM dbo.Students
    WHERE Major = @MajorName AND Age >= @MinimumAge;
END;
GO
EXEC dbo.FindStudents
    @MajorName = 'Computer Science',
    @MinimumAge = 21;

Expected: Cara only. Ana is 20.

Example 9: Optional/default parameter

CREATE OR ALTER PROCEDURE dbo.GetStudentsAboveGPA
    @MinimumGPA DECIMAL(3,2) = 3.50
AS
BEGIN
    SET NOCOUNT ON;
    SELECT StudentName, GPA FROM dbo.Students
    WHERE GPA >= @MinimumGPA
    ORDER BY GPA DESC;
END;
GO
EXEC dbo.GetStudentsAboveGPA;                 -- Uses 3.50
EXEC dbo.GetStudentsAboveGPA @MinimumGPA = 3.90;

Expected: First call returns Cara, Ana, Eva. Second returns Cara only.

Example 10: OUTPUT parameter

An OUTPUT parameter sends a value back to the caller. Declare a variable in the calling batch and pass it using OUTPUT.

CREATE OR ALTER PROCEDURE dbo.GetMajorStudentCount
    @MajorName VARCHAR(60),
    @Total INT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;
    SELECT @Total = COUNT(*)
    FROM dbo.Students
    WHERE Major = @MajorName;
END;
GO
DECLARE @Result INT;
EXEC dbo.GetMajorStudentCount
    @MajorName = 'Mathematics',
    @Total = @Result OUTPUT;
SELECT @Result AS MathematicsStudents;

Expected: MathematicsStudents = 2.

Example 11: Input and OUTPUT parameters together

CREATE OR ALTER PROCEDURE dbo.GetAverageGPAForMajor
    @MajorName VARCHAR(60),
    @AverageGPA DECIMAL(4,2) OUTPUT
AS
BEGIN
    SET NOCOUNT ON;
    SELECT @AverageGPA = AVG(GPA)
    FROM dbo.Students WHERE Major = @MajorName;
END;
GO
DECLARE @Avg DECIMAL(4,2);
EXEC dbo.GetAverageGPAForMajor
    @MajorName = 'Computer Science',
    @AverageGPA = @Avg OUTPUT;
SELECT @Avg AS AverageGPA;

Expected: The average of 3.80 and 3.95, displayed rounded to two decimal places according to SQL Server's decimal conversion rules.

Compare: A SELECT inside a procedure returns a result set; an OUTPUT parameter returns a value through a caller-supplied variable. They are different mechanisms.

5. Stored procedures for INSERT, UPDATE, DELETE (CRUD)

CRUD stands for Create, Read, Update, Delete. The earlier SELECT procedures demonstrate reading. Now practice modifying data. Run these examples in order.

Example 12: Insert a student

CREATE OR ALTER PROCEDURE dbo.AddStudent
    @StudentID INT,
    @StudentName VARCHAR(60),
    @Age INT,
    @Major VARCHAR(60),
    @GPA DECIMAL(3,2)
AS
BEGIN
    SET NOCOUNT ON;
    INSERT INTO dbo.Students
        (StudentID, StudentName, Age, Major, GPA)
    VALUES
        (@StudentID, @StudentName, @Age, @Major, @GPA);
END;
GO
EXEC dbo.AddStudent
    @StudentID = 107, @StudentName = 'Grace',
    @Age = 20, @Major = 'Physics', @GPA = 3.60;
SELECT * FROM dbo.Students WHERE StudentID = 107;

Expected: Grace is added. Running the same INSERT again will fail because StudentID is a primary key.

Example 13: Update a student's major

CREATE OR ALTER PROCEDURE dbo.ChangeStudentMajor
    @StudentID INT,
    @NewMajor VARCHAR(60)
AS
BEGIN
    SET NOCOUNT ON;
    UPDATE dbo.Students
    SET Major = @NewMajor
    WHERE StudentID = @StudentID;
END;
GO
EXEC dbo.ChangeStudentMajor
    @StudentID = 107, @NewMajor = 'Mathematics';
SELECT * FROM dbo.Students WHERE StudentID = 107;

Expected: Grace's major becomes Mathematics.

Example 14: Delete a student

CREATE OR ALTER PROCEDURE dbo.RemoveStudent
    @StudentID INT
AS
BEGIN
    SET NOCOUNT ON;
    DELETE FROM dbo.Students
    WHERE StudentID = @StudentID;
END;
GO
EXEC dbo.RemoveStudent @StudentID = 107;
SELECT * FROM dbo.Students WHERE StudentID = 107;

Expected: No rows returned for ID 107. Other students remain.

Safety: A DELETE or UPDATE without an appropriate WHERE clause can affect every row. Use the practice database only. Production procedures need permission controls, validation, and often transactions.

6. Nested stored procedures: one procedure calls another

A nested stored procedure is a procedure executed from within another procedure. This is useful for reusing existing database operations.

Example 15: A procedure calls a non-parameterized procedure

First, ensure dbo.CountStudents exists from Example 2. Now create another procedure that calls it.

CREATE OR ALTER PROCEDURE dbo.ShowCollegeSummary
AS
BEGIN
    SET NOCOUNT ON;
    PRINT 'College summary begins';
    EXEC dbo.CountStudents;
    PRINT 'College summary ends';
END;
GO
EXEC dbo.ShowCollegeSummary;

Execution flow: ShowCollegeSummary → CountStudents → SELECT COUNT(*) → return to ShowCollegeSummary. The Messages tab shows PRINT output; the Results tab shows the count.

Example 16: A parent passes parameters to a child

First, use the existing GetStudentsByMajor procedure from Example 7. Then create a parent procedure.

CREATE OR ALTER PROCEDURE dbo.MajorReport
    @RequestedMajor VARCHAR(60)
AS
BEGIN
    SET NOCOUNT ON;
    PRINT 'Showing selected major';
    EXEC dbo.GetStudentsByMajor
        @MajorName = @RequestedMajor;
END;
GO
EXEC dbo.MajorReport @RequestedMajor = 'Physics';

Expected: Frank's record. The parent receives @RequestedMajor and passes its value to the child parameter @MajorName.

Example 17: Three-level nesting

CREATE OR ALTER PROCEDURE dbo.LevelOne
AS
BEGIN
    PRINT 'Level 1: start';
    EXEC dbo.LevelTwo;
    PRINT 'Level 1: end';
END;
GO
CREATE OR ALTER PROCEDURE dbo.LevelTwo
AS
BEGIN
    PRINT 'Level 2: start';
    EXEC dbo.LevelThree;
    PRINT 'Level 2: end';
END;
GO
CREATE OR ALTER PROCEDURE dbo.LevelThree
AS
BEGIN
    PRINT 'Level 3: running';
END;
GO
EXEC dbo.LevelOne;

Expected Messages order: Level 1: start → Level 2: start → Level 3: running → Level 2: end → Level 1: end.

Example 18: Nested procedure with OUTPUT value

CREATE OR ALTER PROCEDURE dbo.ShowMajorCountMessage
    @MajorName VARCHAR(60)
AS
BEGIN
    SET NOCOUNT ON;
    DECLARE @NumberOfStudents INT;
    EXEC dbo.GetMajorStudentCount
        @MajorName = @MajorName,
        @Total = @NumberOfStudents OUTPUT;
    SELECT @MajorName AS Major,
           @NumberOfStudents AS StudentCount;
END;
GO
EXEC dbo.ShowMajorCountMessage @MajorName = 'Mathematics';

Expected: Mathematics, 2. The child fills the output variable; the parent uses it.

Important: SQL Server supports nesting stored procedures up to 32 levels. A stored procedure is not the same as a SQL function; a procedure is normally invoked with EXEC, not embedded directly inside a SELECT expression.

7. Useful additional techniques

Example 19: Change an existing procedure

ALTER PROCEDURE dbo.GetAllStudents
AS
BEGIN
    SET NOCOUNT ON;
    SELECT StudentID, StudentName, Age, Major, GPA
    FROM dbo.Students
    ORDER BY StudentName ASC;
END;
GO
EXEC dbo.GetAllStudents;

Expected: Students ordered alphabetically by name. ALTER modifies the procedure definition without recreating the Students table.

Example 20: IF / ELSE inside a procedure

CREATE OR ALTER PROCEDURE dbo.CheckStudentExists
    @StudentID INT
AS
BEGIN
    SET NOCOUNT ON;
    IF EXISTS (SELECT 1 FROM dbo.Students
               WHERE StudentID = @StudentID)
        SELECT 'Student found' AS Message;
    ELSE
        SELECT 'Student not found' AS Message;
END;
GO
EXEC dbo.CheckStudentExists @StudentID = 101;
EXEC dbo.CheckStudentExists @StudentID = 999;

Expected: “Student found”, then “Student not found”.

Example 21: TRY / CATCH and THROW

CREATE OR ALTER PROCEDURE dbo.AddStudentSafely
    @StudentID INT,
    @StudentName VARCHAR(60),
    @Age INT,
    @Major VARCHAR(60),
    @GPA DECIMAL(3,2)
AS
BEGIN
    SET NOCOUNT ON;
    BEGIN TRY
        INSERT INTO dbo.Students
            (StudentID, StudentName, Age, Major, GPA)
        VALUES
            (@StudentID, @StudentName, @Age, @Major, @GPA);
    END TRY
    BEGIN CATCH
        PRINT 'Insert failed: ' + ERROR_MESSAGE();
        THROW;
    END CATCH;
END;
GO
-- Intentional duplicate-key error for demonstration:
EXEC dbo.AddStudentSafely
    @StudentID = 101, @StudentName = 'Duplicate',
    @Age = 20, @Major = 'Physics', @GPA = 3.00;

Expected: A duplicate primary-key error. The CATCH block prints the error and THROW passes it to the caller. No duplicate row is inserted.

Example 22: Transaction with two updates

For a realistic example, transfer points between two accounts. Both updates must succeed together.

IF OBJECT_ID('dbo.PointAccounts', 'U') IS NULL
BEGIN
    CREATE TABLE dbo.PointAccounts (
        AccountID INT PRIMARY KEY,
        Points INT NOT NULL CHECK (Points >= 0)
    );
    INSERT INTO dbo.PointAccounts VALUES (1, 100), (2, 50);
END;
GO
CREATE OR ALTER PROCEDURE dbo.TransferPoints
    @FromID INT,
    @ToID INT,
    @Amount INT
AS
BEGIN
    SET NOCOUNT ON;
    SET XACT_ABORT ON;
    IF @Amount <= 0 OR @FromID = @ToID
        THROW 50001, 'Invalid transfer request.', 1;
    BEGIN TRY
        BEGIN TRANSACTION;
        UPDATE dbo.PointAccounts
        SET Points = Points - @Amount
        WHERE AccountID = @FromID AND Points >= @Amount;
        IF @@ROWCOUNT <> 1
            THROW 50002, 'Source missing or insufficient points.', 1;
        UPDATE dbo.PointAccounts
        SET Points = Points + @Amount
        WHERE AccountID = @ToID;
        IF @@ROWCOUNT <> 1
            THROW 50003, 'Destination account not found.', 1;
        COMMIT TRANSACTION;
    END TRY
    BEGIN CATCH
        IF XACT_STATE() <> 0 ROLLBACK TRANSACTION;
        THROW;
    END CATCH;
END;
GO
EXEC dbo.TransferPoints @FromID = 1, @ToID = 2, @Amount = 20;
SELECT * FROM dbo.PointAccounts ORDER BY AccountID;

Expected on first execution: Account 1 = 80; Account 2 = 70. The transaction prevents partial completion if an update fails.

Example 23: Return status with RETURN

CREATE OR ALTER PROCEDURE dbo.IsStudentPresent
    @StudentID INT
AS
BEGIN
    IF EXISTS (SELECT 1 FROM dbo.Students
               WHERE StudentID = @StudentID)
        RETURN 0;
    RETURN 1;
END;
GO
DECLARE @Status INT;
EXEC @Status = dbo.IsStudentPresent @StudentID = 999;
SELECT @Status AS StatusCode;

Expected: 1 means not found in this example; 0 means found. RETURN is commonly used for integer status codes, whereas OUTPUT parameters return values.

Solution 2 — ShowAverageAge
CREATE OR ALTER PROCEDURE dbo.ShowAverageAge
AS
BEGIN
    SET NOCOUNT ON;
    SELECT AVG(CAST(Age AS DECIMAL(6,2))) AS AverageAge
    FROM dbo.Students;
END;
GO
EXEC dbo.ShowAverageAge;

The original ages sum to 126; 126 ÷ 6 = 21.00. Casting avoids integer-only averaging.

Solution 12 — Explain nesting and OUTPUT

Nesting: A report procedure can call a reusable filtering procedure instead of repeating the same SQL. The outer procedure may supply input parameters to the inner procedure and continue after the inner call finishes.

OUTPUT versus SELECT: An OUTPUT parameter assigns a value to a variable in the caller; SELECT sends a result set back to the client. A procedure may do both.

11. Troubleshooting and review

ProblemWhat to check
“CREATE/ALTER PROCEDURE must be the first statement in a query batch”Put GO before the procedure definition; run its definition as a separate batch.
“Could not find stored procedure”Confirm USE StoredProcLab;, the schema (dbo), and that the creation batch succeeded.
“Procedure expects parameter ...”Supply all required parameters, or define defaults where appropriate.
“Must declare the scalar variable”Declare the caller variable and execute it within the same batch; GO ends variable scope.
Duplicate primary key errorUse a new student ID or remove the previously inserted practice row.
OUTPUT variable remains NULLCheck the child assigns it, the call includes OUTPUT, and the query actually has matching data.
Final recap: No-parameter procedures perform a fixed operation; input parameters customize the operation; OUTPUT parameters return values to the caller; nested procedures reuse other procedures; CRUD procedures modify data; transactions protect related changes.
