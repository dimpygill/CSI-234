1. What is T-SQL programming?

SQL describes which data you want or which rows to change. Transact-SQL (T-SQL), Microsoft's SQL dialect, adds procedural constructs such as DECLARE, SET, IF...ELSE, WHILE, BREAK, and CONTINUE. These are useful for scripting and stored procedures. Most routine data operations should still be expressed with set-based SQL.

3. Variables: DECLARE, SET, and SELECT

Local variable names begin with @. Choose an appropriate data type, such as INT, DECIMAL(3,2), VARCHAR(n), or NVARCHAR(n). A variable declared without a value initially contains NULL. Use SET for straightforward single-variable assignment; SELECT can assign a value from a query. Beware: a SELECT assignment returning multiple rows may repeatedly overwrite the variable, and without an ordering guarantee you should not rely on which value remains.

Scope: Local variables live within their batch or routine, not permanently in the database. GO splits batches in tools such as SSMS.

4. Decisions: IF, ELSE, nested IF, and EXISTS

Use IF to decide which statement to execute. Put BEGIN...END around multiple statements. SQL's three-valued logic includes TRUE, FALSE, and UNKNOWN (often caused by NULL); an IF branch executes only when its condition is TRUE. Use IS NULL for NULL tests.

5. Repetition: WHILE, BREAK, CONTINUE

WHILE is a pre-test loop: the condition is checked before each iteration. Always plan how the condition eventually becomes false. BREAK exits the nearest loop; CONTINUE skips to the next condition check. Place counter updates before CONTINUE when necessary.

6. Worked T-SQL examples

Read each example, predict its result, then reveal the explanation.

1. Declare and display a variable

DECLARE @StudentName NVARCHAR(50) = N'Asha';
SELECT @StudentName AS StudentName;
Expected output:
Asha

Why: DECLARE creates a local variable. SELECT displays its current value.

2. SET and arithmetic

DECLARE @Credits INT = 12;
SET @Credits = @Credits + 3;
SELECT @Credits AS Credits;
Expected output:
15

Why: SET updates a variable; arithmetic expressions are evaluated before assignment.

3. SELECT assignment from a query

DECLARE @Count INT;
SELECT @Count = COUNT(*) FROM dbo.Students;
SELECT @Count AS StudentCount;
Expected output:
Depends on table rows

Why: COUNT(*) counts matching rows. A SELECT assignment can populate a variable from a query.

4. IF / ELSE

DECLARE @GPA DECIMAL(3,2) = 3.70;
IF @GPA >= 3.50
    PRINT 'Honors eligible';
ELSE
    PRINT 'Not eligible';
Expected output:
Honors eligible

Why: IF executes one statement when its Boolean condition is true; ELSE handles false or unknown.

5. IF with BEGIN / END

DECLARE @Credits INT = 15;
IF @Credits >= 12
BEGIN
    PRINT 'Full-time';
    PRINT 'Review financial aid';
END
ELSE
BEGIN
    PRINT 'Part-time';
END;
Expected output:
Full-time; Review financial aid

Why: BEGIN and END group multiple statements into one branch.

6. Nested IF

DECLARE @GPA DECIMAL(3,2) = 3.85;
DECLARE @Credits INT = 12;
IF @Credits >= 12
BEGIN
    IF @GPA >= 3.75 PRINT 'Dean''s list candidate';
    ELSE PRINT 'Full-time';
END
ELSE PRINT 'Part-time';
Expected output:
Dean's list candidate

Why: Nested decisions test one condition inside another. Eligibility rules here are illustrative.

7. IF EXISTS with a table

IF EXISTS (SELECT 1 FROM dbo.Students WHERE Major = 'CS')
    PRINT 'At least one CS student';
ELSE
    PRINT 'No CS students';
Expected output:
At least one CS student (with sample data)

Why: EXISTS checks whether a subquery returns at least one row, without requiring a row count.

8. WHILE counting

DECLARE @i INT = 1;
WHILE @i <= 5
BEGIN
    PRINT @i;
    SET @i += 1;
END;
Expected output:
1, 2, 3, 4, 5

Why: The loop reevaluates its condition before every iteration. Incrementing prevents an infinite loop.

9. WHILE accumulator

DECLARE @n INT = 1, @total INT = 0;
WHILE @n <= 4
BEGIN
    SET @total += @n;
    SET @n += 1;
END;
SELECT @total AS SumOfFirstFour;
Expected output:
10

Why: The accumulator stores 1+2+3+4 while the counter tracks iterations.

10. BREAK

DECLARE @n INT = 0;
WHILE @n < 10
BEGIN
    SET @n += 1;
    IF @n = 4 BREAK;
    PRINT @n;
END;
Expected output:
1, 2, 3

Why: BREAK exits the nearest WHILE immediately.

11. CONTINUE

DECLARE @n INT = 0;
WHILE @n < 5
BEGIN
    SET @n += 1;
    IF @n = 3 CONTINUE;
    PRINT @n;
END;
Expected output:
1, 2, 4, 5

Why: CONTINUE skips the rest of the current iteration; increment happens first.

12. CASE in SELECT

SELECT Name, GPA,
       CASE WHEN GPA >= 3.5 THEN 'High'
            WHEN GPA >= 3.0 THEN 'Good'
            ELSE 'Developing' END AS GPAGroup
FROM dbo.Students;
Expected output:
Asha: High; Ben: Good; Cara: Developing; Diego: High; Emi: Good

Why: CASE is an expression producing a value for each row, unlike IF which controls statements.

13. UPDATE using a condition

DECLARE @Bonus DECIMAL(3,2) = 0.10;
UPDATE dbo.Students
SET GPA = GPA + @Bonus
WHERE StudentID = 3 AND GPA + @Bonus <= 4.00;
SELECT Name, GPA FROM dbo.Students WHERE StudentID = 3;
Expected output:
Cara: 2.90

Why: WHERE limits which row is updated. Reset sample data before rerunning to avoid repeated changes.

14. Loop over numbered steps

DECLARE @Step INT = 1;
WHILE @Step <= 3
BEGIN
    PRINT CONCAT('Processing step ', @Step);
    SET @Step = @Step + 1;
END;
Expected output:
Processing step 1; Processing step 2; Processing step 3

Why: CONCAT constructs messages; a loop is appropriate for repeated procedural steps.

15. NULL and IF

DECLARE @Score INT = NULL;
IF @Score >= 60 PRINT 'Pass';
ELSE PRINT 'No passing score recorded';
Expected output:
No passing score recorded

Why: A comparison to NULL yields UNKNOWN, not TRUE; IF only enters its first branch for TRUE.

16. Safe NULL handling

DECLARE @Score INT = NULL;
IF @Score IS NULL
    PRINT 'Score missing';
ELSE IF @Score >= 60
    PRINT 'Pass';
ELSE
    PRINT 'Fail';
Expected output:
Score missing

Why: IS NULL explicitly detects missing values.

17. Batch scope and GO

DECLARE @X INT = 7;
SELECT @X AS FirstBatch;
GO
-- @X is not available after GO.
DECLARE @X INT = 9;
SELECT @X AS SecondBatch;
Expected output:
FirstBatch: 7; SecondBatch: 9

Why: GO is a client-tool batch separator, not a T-SQL statement; local variables are batch-scoped.

18. Set-based alternative to a loop

UPDATE dbo.Students
SET Credits = Credits + 1
WHERE Major = 'CS';
SELECT Name, Credits FROM dbo.Students WHERE Major = 'CS';
Expected output:
Asha: 16; Cara: 10; Emi: 13 (fresh sample)

Why: One set-based UPDATE modifies all matching rows. Prefer this to row-by-row loops when possible.

7. Programming-language design perspective

TaskT-SQLC / C# / Python comparison
VariableDECLARE @x INT = 1;Typed declaration in C/C#; assignment in Python
DecisionIF @x > 0 ... ELSE ...Similar control-flow idea; T-SQL uses BEGIN/END instead of braces or indentation
LoopWHILE @x < 5 ...Similar pre-test loop, but SQL excels at set-based operations
Per-row labelCASE expression in SELECTExpression returns a value for each row
Bulk updateUPDATE ... WHERE ...Declarative set operation, not an explicit row iteration

Design question: Why does SQL have loops if it is declarative? T-SQL combines a declarative relational core with procedural scripting features. Use procedural flow to orchestrate operations; use set-based statements to manipulate collections of rows.

10. Additional practice challenges with detailed solutions

Challenge A — Classify credit loads

Declare a credit-load variable. Print “Full-time” when credits are at least 12; otherwise print “Part-time.” Test values 9 and 15.

View solution and reasoning
DECLARE @Credits INT = 9;
IF @Credits >= 12 PRINT 'Full-time';
ELSE PRINT 'Part-time';
-- Change @Credits to 15 and run again.

With 9, the condition is false and the output is Part-time. With 15, it is true and the output is Full-time. The threshold is an illustrative rule.

Challenge B — Sum even numbers 2 through 10

Write a WHILE loop and predict the final total.

View solution and reasoning
DECLARE @n INT = 2, @total INT = 0;
WHILE @n <= 10
BEGIN
    SET @total += @n;
    SET @n += 2;
END;
SELECT @total AS Total;

The loop visits 2, 4, 6, 8, 10 and produces 30. The counter increases by 2, so it terminates at 12.

Challenge C — Replace a procedural idea with a set-based statement

Give every student with fewer than 12 credits one additional credit. Explain why a loop is unnecessary.

View solution and reasoning
UPDATE dbo.Students
SET Credits = Credits + 1
WHERE Credits < 12;

SQL Server applies the operation to all qualifying rows as one set. On the original sample, Ben and Cara change from 9 to 10. A WHILE loop would add needless complexity.

Challenge D — Handle missing GPA correctly

Print “Missing GPA,” “Honors,” or “Standard” for a single GPA variable, in that priority order.

View solution and reasoning
DECLARE @GPA DECIMAL(3,2) = NULL;
IF @GPA IS NULL
    PRINT 'Missing GPA';
ELSE IF @GPA >= 3.50
    PRINT 'Honors';
ELSE
    PRINT 'Standard';

Check NULL first. Comparing NULL with 3.50 does not produce TRUE or FALSE, so an explicit missing-value branch avoids misclassification.

11. Key takeaways

DECLARE creates variables; SET assigns values; IF/ELSE selects execution paths; BEGIN/END groups statements; WHILE repeats; BREAK exits; CONTINUE skips the remainder of an iteration; and CASE computes a value inside SQL expressions. Favor set-based queries for operations on many rows.
